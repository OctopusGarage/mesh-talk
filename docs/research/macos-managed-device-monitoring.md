# Managed macOS surveillance threat model

Research date: 2026-10-12. This note describes **platform capabilities**, not evidence that a particular employer is using them. Actual exposure depends on device management, installed software, granted permissions, and whether the app is unlocked or has placed data outside its encrypted store.

## What a managed Mac may expose

| Channel | What Apple documents | Consequence for Mesh Talk |
| --- | --- | --- |
| Screen recording, screenshots, and remote observation | Apps granted **Screen & System Audio Recording** can record the display. Separately, an MDM **Enable Remote Desktop** command turns on Remote Management with Observe and Control privileges; Apple Remote Desktop can save a picture of the remote screen. The MDM privacy-policy profile's `ScreenCapture` entry cannot itself grant ordinary screen-capture access, but this does not remove the separate Remote Management route. [Screen recording settings](https://support.apple.com/guide/mac-help/control-access-screen-system-audio-recording-mchld6aa7d23/mac); [MDM Remote Management](https://support.apple.com/en-ca/102024); [Remote Desktop capture](https://support.apple.com/en-mide/guide/remote-desktop/apdea1dcde8/mac); [privacy-policy payload](https://developer.apple.com/documentation/devicemanagement/privacypreferencespolicycontrol/services-data.dictionary) | Messages, images, filenames, contacts, and identity details visible in an unlocked window can be copied as pixels. An app cannot infer from MDM enrollment alone whether observation is active. |
| Keyboard, mouse, and UI control | Apple describes **Input Monitoring** as allowing an app to see what is typed and mouse/trackpad input, and **Accessibility** as allowing scripts and system commands to control the Mac. These permissions are visible under Privacy & Security. [macOS privacy settings](https://support.apple.com/en-au/guide/mac-help/mchl211c911f/mac) | Passwords and message drafts may be exposed as the user types. A lock screen or Touch ID prompt does not conceal keystrokes from an input monitor authorized by the OS. |
| Local files and app data | **Full Disk Access** permits access to files from other apps; macOS also has a distinct permission for other apps' data. MDM privacy settings can define policies for `SystemPolicyAllFiles` and `SystemPolicyAppData`. [macOS privacy settings](https://support.apple.com/en-au/guide/mac-help/mchl211c911f/mac); [privacy-policy payload](https://developer.apple.com/documentation/devicemanagement/privacypreferencespolicycontrol/services-data.dictionary) | A plaintext database, attachment cache, log, crash report, temporary file, or exported file is a potential disclosure route. Encryption of the primary store helps only if keys are unavailable and the content has not been duplicated in plaintext. |
| Endpoint security and network filtering | Apple says Endpoint Security extensions can monitor or block system events such as process execution, forks, and file-related activity. Managed content filtering includes DNS proxy and advanced filtering of web and socket traffic. [Endpoint Security](https://developer.apple.com/documentation/EndpointSecurity); [system extensions](https://developer.apple.com/system-extensions/); [content filtering](https://support.apple.com/guide/deployment/filter-content-dep1129ff8d2/web) | Software can learn that the app ran, what files it touched, and network destinations or timing. End-to-end encryption can protect message content in transit but cannot hide all metadata, on-screen plaintext, or endpoint activity. |
| Clipboard and notifications | AppKit's general pasteboard is shared between apps and participates in Universal Clipboard. macOS notification previews can be shown even at the login window if configured to **Always**, and notification settings also govern lock-screen and screen-sharing display. [NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard); [notification settings](https://support.apple.com/en-gb/guide/mac-help/mh40583/26/mac/26) | Copying message text or including message bodies in notifications can expose content outside the app's protected storage and UI. |
| Keychain | Apple's keychain enforces access through `securityd` and app identity/access groups; items can require user presence or Touch ID through access-control policies. [Keychain data protection](https://support.apple.com/en-nz/guide/security/secb0694df1a/web) | Keychain-backed secrets can reduce at-rest exposure, but keychain storage does not prevent observation of content after the app decrypts and displays it. |

## Security boundary

No normal macOS chat app can guarantee that its visible content is hidden from a Mac's operator, authorized screen recording, remote observation, input monitoring, or a camera aimed at the display. In particular, Apple's current documentation calls `NSWindow.SharingType.none` a **legacy constant that macOS no longer uses** and explicitly says not to use it to hide content from capture. Apple's app-protected-content capture entitlement is documented for **visionOS**, not as a general macOS window protection. [NSWindow sharing](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none); [app-protected content](https://developer.apple.com/documentation/BundleResources/Entitlements/com.apple.developer.protected-content)

The useful promise is narrower: reduce how often plaintext is displayed, copied, logged, cached, and retained; keep keys protected when the app is locked; and explain to users that a managed or monitored device can observe information they view or type. Do not present screenshot blocking, capture detection, or Touch ID as protection against device administrators.

## Worthwhile default hardening

1. **Keep notification payloads content-free by default.** Show only a generic new-message signal; let users opt into previews with an explicit warning. This removes one plaintext path to Notification Center and screen-sharing views. [Notification settings](https://support.apple.com/en-gb/guide/mac-help/mh40583/26/mac/26)
2. **Review all plaintext output paths.** Audit logs, panic/crash reports, caches, temporary attachments, thumbnails, exports, and OS recent-items integration. Ensure sensitive content is not written by default, and remove temporary files promptly. This directly addresses Full Disk Access and app-data access exposure. [macOS privacy settings](https://support.apple.com/en-au/guide/mac-help/mchl211c911f/mac)
3. **Make lock behavior meaningful.** On lock/background/idle, clear rendered message state and media previews where practical; require authentication before reloading secrets. Use Keychain access-control policy for retained secrets where compatible with session behavior. This limits unattended viewing and at-rest key exposure, while leaving active-session capture as a known limit. [Keychain data protection](https://support.apple.com/en-nz/guide/security/secb0694df1a/web)
4. **Treat copy and export as explicit disclosure actions.** Avoid automatic copying, provide a clear warning for sensitive copying, and clear only app-owned clipboard content after a short period if such a feature is offered. Because the pasteboard is shared, never describe timed clearing as guaranteed secrecy. [NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard)
5. **Tell users the device-trust boundary.** A short in-app security explanation should say that company-managed devices may observe the display, input, files, and network metadata, and recommend a personally controlled device for conversations that must remain private from the device operator. This follows directly from the documented platform capabilities above.

Do not add an `NSWindowSharingNone` setting or a screenshot-prevention claim. Neither would establish the protection users need. [NSWindow sharing](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none)
