# Managed-device security audit (macOS)

Date: 2026-10-12. Scope: the current `optimize/targeted` checkout, the shipped Tauri desktop app, and a Mac managed by an employer. This is a source review, not a test of any particular employer's monitoring software or policies. Platform facts and their limits are sourced in [the macOS monitoring research](../research/macos-managed-device-monitoring.md).

> The risk table below records the **pre-hardening code** reviewed at the start of this work. The implementation status near the end of this document records the changes on this branch. Keeping the original findings makes the before/after comparison auditable.

## Answer and trust boundary

**Yes, the app can be monitored on a managed Mac.** End-to-end encryption protects message content in transit and the app encrypts its main history and credentials at rest; neither protects plaintext while it is displayed, copied, notified, exported, or held in a running process. A device administrator may deploy screen observation, endpoint agents, network filters, and management profiles. Whether any specific employer actually does so cannot be determined from this repository. An app cannot reliably detect all such tools or prevent all screenshots, and it must not promise that a managed device is private.

The practical boundary is: Mesh-Talk can minimize what it reveals through its own UI, files, logs, and webview permissions. It cannot enforce confidentiality against the owner or administrator of the operating system, a person with the unlocked desktop, or another participant who records a conversation.

## Existing protections and limits

- The protocol uses authenticated Noise transport, encrypted event and message stores, and end-to-end DM/channel encryption ([architecture](../ARCHITECTURE.md)). These protect the network path and core durable history.
- A saved macOS sign-in password is held in the standard OS Keychain (`src-tauri/src/session_store/macos.rs`) for automatic login. An already-unlocked OS account can resume Mesh-Talk. A separate Touch ID item supports the in-app lock screen; neither hides an already-unlocked session or message plaintext from the host OS.
- `retention_days` can prune older history, but defaults to `0` (forever) in `src-tauri/src/settings.rs`. Existing copies, recipient devices, exports, and backups are outside a local prune.
- The app's screenshot feature is invoked by a user action and requests macOS Screen Recording access when used. Removing that feature would not revoke another app's independent capture permission.

## Hardening choices, in recommended order

1. **Make notifications content-free by default.** Route all inbound notification delivery through one owner (prefer the native backend when the window is unfocused); use a generic title/body with no sender, channel, filename, or message text. Provide an explicit opt-in to previews if desired. Keep badge/unread behavior. Verify one notification per event, foreground suppression, settings migration, and lock-screen behavior on macOS. This directly removes a verified leak and likely duplicate alerts.
2. **Remove unused webview filesystem authority and add a tested CSP.** Drop recursive home read/write grants from both capability files, and remove the filesystem plugin if no feature needs it. Narrow or remove shell/open-path permissions after tracing every UI call; turn off `withGlobalTauri` if the UI does not need the global API. Add a production CSP that permits only bundled scripts/styles/assets and required blob/data URLs; check marketplace fetches and WebRTC. Verify on a packaged macOS build, because Vite development and WKWebView can differ. This reduces a renderer compromise's reach; CSP is defense in depth, not a capture blocker. [Tauri CSP](https://v2.tauri.app/security/csp/); [Tauri capabilities](https://v2.tauri.app/reference/acl/capability/).
3. **Protect plaintext media at rest.** Replace durable plaintext `media/` files with per-account authenticated encryption, decrypt only when serving an authorized preview/export, and migrate existing files safely. Also create app directories and files with owner-only permissions on Unix, without following symlinks for sensitive paths. Define retention behavior for media, temporary capture files, and downloads; do not silently delete user exports. This is substantial core/storage work requiring crash and migration tests.
4. **Reduce session exposure.** Offer a short idle/background lock policy, with reauthentication before showing decrypted chats after a timeout. Make the default short enough to reduce unattended display time, but do not claim it defeats capture while the window is visible or privileged endpoint tooling. Test calls, tray background delivery, and lost/recovered Touch ID.
5. **Minimize incidental copies.** Avoid persistent sensitive diagnostic fields; use safer log defaults in release builds. Show a short warning before copying a link code or message to the shared clipboard and consider an optional timed clear only if the clipboard still contains the value the app placed there. Expose the managed-device limitation plainly in the security/privacy UI.

Three implementation paths are possible: (A) small exposure reduction (notification de-duplication and private defaults), (B) client boundary hardening (A plus capability/CSP audit), or (C) full local-data redesign (B plus encrypted media and session locking). **B is the best first milestone**: it removes a confirmed plaintext broadcast and excessive webview authority without changing the on-disk format. C should follow as a separately reviewed storage migration. None makes a company-managed Mac immune to observation.

## Implementation on `optimize/targeted`

The user selected **Balanced** as the default to preserve the existing experience. It keeps notification previews, direct copying, and no automatic lock. **Private** uses generic notifications, a 10-minute idle lock, and a 60-second conditional clipboard clear. **Strict** uses generic notifications, a one-minute idle lock, immediate lock when hidden, copy confirmation, and a 30-second conditional clear. Every control can be edited independently; editing a preset marks it Custom. Existing settings JSON fields default to the old interaction pattern.

Rust now owns the single native notification path. The frontend reports the visible conversation with a monotonic revision, and no longer sends a second browser notification. Locked sessions always use a generic notification and suppress plaintext Tauri chat events. The native lock blocks new app IPC except lock status, unlock, logout, and app-owned temp cleanup; the node stays online. macOS unlock reads the separate Touch ID protected Keychain credential only when Stay signed in is enabled, then verifies it against the active account without starting a second runtime. Password entry remains available. The native idle timer checks the saved policy even if the webview pauses; calls suspend automatic locking, while manual locking ends the call.

Durable media uses a versioned, chunked AES-256-GCM format with local device owner, conversation, size, and chunk index authenticated as associated data. New copies are staged with owner-only permissions and atomically renamed after verification. Successful account unlock migrates legacy plaintext files; a failed migration retains a readable source and shows an in-app warning so a restart can retry. Local media is removed when its last local file card is erased. Pasted media staging uses private directories/files and is cleaned after send or on startup. Explicit user exports stay plaintext in the chosen destination. Existing backups and snapshots can still contain old plaintext.

The webview no longer has recursive home filesystem grants, the unused filesystem and shell plugins, or the global Tauri API. A production CSP constrains scripts, assets, and network connections. The download-folder action now runs through a native command that opens the configured or default directory with Finder on macOS; the renderer no longer has direct permission to open arbitrary paths. A compromised renderer can still change the configured download directory through settings, so this is reduced authority rather than a full path allowlist. The remaining reveal-in-file-manager permission accepts a path from the renderer and can expose local path metadata if that renderer is compromised. Release logging is limited to warnings/errors in a private log directory. Conditional clipboard clearing skips the action when the clipboard cannot be read or has changed.

The lock is an access gate for **new** app IPC, and the frontend invalidates old ownership leases when it hides chat state. Critical history, search, and media read commands also recheck the lock before returning, but other app IPC requests already executing at the instant of lock may still finish and deliver a response to the webview. The UI does not render stale responses after lock; renderer memory is still a residual exposure. Full native response-time rejection requires a Tauri response interception path or command-by-command post-work checks. Clipboard clearing is also best effort: another copy between its read and clear calls can race with it. Likewise, neither this lock nor the CSP protects against privileged OS screen, input, file, or process monitoring.

## Validation on this branch

- `./scripts/check-health.sh` passed on macOS: formatting, Clippy, spelling, cargo-deny, cargo-machete, gitleaks, shellcheck, actionlint, frontend typecheck/lint, 306 Vitest tests, 274 Playwright cases (2 skipped), the Rust workspace suite, npm audit, and workspace builds.
- `cargo tauri build --bundles app` produced a macOS `.app` with the production CSP and narrowed capabilities.
- Focused Playwright runs passed for privacy levels, settings recovery, pasted files, media lifecycle (7 cases), dialog layout, and visual regression (23 cases).
- A focused folder-recovery Playwright run passed after the native-only download-folder change (2 cases); Clippy, frontend typecheck, lint, and formatting checks were rerun for that change.
- Native unit tests cover policy migration, notification payload decisions, encrypted media tampering and legacy migration, permissions and symlink handling, startup pruning, and lock admission. These tests do not simulate a managed Mac or a real Touch ID prompt.

## Manual validation still needed

- Run a packaged macOS app and inspect actual notification title/body on a locked screen, including DM/channel/file events and both focused/unfocused states.
- Exercise the packaged app's marketplace, downloads, external links, capture, and calls with CSP enabled. Test Touch ID cancellation, password fallback, background delivery, and logout on a physical Mac; run Windows/Linux UI smoke checks. The automated build and browser mocks do not prove those native flows.
- Inspect an upgraded real account's media after migration and confirm its existing previews and exports, including an interrupted migration restart. Unit fixtures cover the storage behavior, but no real user account was migrated here.
- Treat any screen-capture exclusion experiment as a convenience only. Apple explicitly says `NSWindow.SharingType.none` is a legacy value that must not be used to hide content from capture.
